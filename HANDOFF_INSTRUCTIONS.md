## 1. Статус карточек локаций — ГОТОВО, стабильная версия

Реализована новая фича: при выборе конкретной локации в выпадающем списке (`locationSelect`) над списком рыб показывается карточка локации (`renderLocationCard()` + CSS `.location-card`).

### Утверждённый вид карточки (эталон, зафиксирован пользователем):
- Фоновое фото на весь блок, поверх — полупрозрачная стеклянная панель (`.loc-panel`, `rgba(20,30,25,0.55)`, `backdrop-filter: blur(3px)`, ширина 50% (от середины карточки)
- Название локации — **без иконки**, ярко-белым (`#ffffff`)
- «Стоимость поездки» и «Необходимый разряд» — сдвинуты вправо на **30 неразрывных пробелов** (`\u00A0`, вставлены прямо в текст в шаблоне, НЕ через CSS margin/padding — это принципиально, только так сработало), значения/иконки — на своих обычных местах (как у остальных строк, через flex + `justify-content: space-between`)
- «Погода», «Насыщение рыбой», «Загрязнение» — **не трогать**, остаются в исходном положении
- «Видов рыб на локации» — по центру, цвет `#4caf50` (как у counter-box «Найдено видов рыб» под строкой поиска), шрифт увеличен на 2pt (15px), равные отступы сверху/снизу (по 16px от разделителя и от края плашки)
- Тени добавлены на все текстовые элементы для читаемости на фоне фото

### ⚠️ Важный урок (чтобы не повторять ошибку):
Один раз потратили 3 итерации на баг с центрированием строк «Стоимость поездки»/«Необходимый разряд» — причина была в CSS-селекторе `:first-of-type`, который смотрит на позицию среди **всех тегов `<div>`**, а не среди элементов с нужным классом. Перед первой `.loc-stat-group` в разметке стоит `<div class="loc-title">` — тоже `<div>` — из-за этого селектор никогда не совпадал. Решение: **всегда использовать явные классы** (например, добавлен класс `loc-stat-primary` вручную в шаблоне), не полагаться на структурные псевдоклассы типа `:first-of-type`/`:first-child` при разметке, сгенерированной в цикле.

## 2. Фоны локаций — метод добавления

**Копирайт:** фоны локаций **из самой игры** (скриншоты) использовать нельзя — это чужие лицензированные фото/арт. Пользователь присылает **свои собственные изображения** (AI-генерация или личные фото из открытых источников) — только их и встраивать.

### Технический процесс (уже отработан, повторять один в один):
```python
from PIL import Image
import base64, os

img = Image.open('/mnt/user-data/uploads/<файл>.png').convert('RGB')
target_w = 900
ratio = target_w / img.width
target_h = int(img.height * ratio)
img_resized = img.resize((target_w, target_h), Image.LANCZOS)
img_resized.save('/home/claude/bg_<location>.jpg', quality=82, optimize=True)

with open('/home/claude/bg_<location>.jpg', 'rb') as f:
    b64 = base64.b64encode(f.read()).decode()
```
Затем вставить `bgImage:'data:image/jpeg;base64,{b64}'` в соответствующую запись объекта `locationsData` (JS, в `<script>` секции файла) — добавить как последнее поле к существующей записи локации.

После каждой вставки: извлечь `<script>` в отдельный `.js` файл и проверить `node --check` на синтаксис, затем скопировать файл в `/mnt/user-data/outputs/` и вызвать `present_files`.

## 4. Карточки рыб — НЕ НАЧАТО (следующая крупная задача)

Все нужные данные для пересборки карточек рыб **уже посчитаны** и лежат в `MFWDB_updated.json` (поле `computed` на каждой рыбе):
- `price_preliminary` — цена (⚠️ формула для обычной/не-монстр рыбы **предварительная**, не подтверждена окончательно — см. п.5)
- `dohodnost_preliminary` — доходность (цена × скорость поимки, скорость зависит от веса рыбы, а не только от флага монстр/луна)
- `hook_min` / `hook_max` — диапазон крючка по весу вида
- `best_location` / `best_bait` + `alternatives` — лучший вариант локации/наживки с фолбэками
- `is_farm_tag` — кандидат на тег «💰 Фарм»

Согласованный формат карточки рыбы (из более ранней переписки, ещё не реализован в HTML):
- Локация/Наживка: лучший вариант первым, альтернативы в скобках
- Вес: `мин – макс` (кг)
- Крючок: `#мин – #макс`, цвет **`#ffc107`** (янтарный, чтобы не совпадать с тегом «Фарм» `#ff9800` и тегом «С приловом» `#ffeb3b`)
- Убрать строку «Стоимость», на её место (после звёзд рейтинга) — «Доходность»

## 5. Формула цены — НЕ РЕШЕНО ОКОНЧАТЕЛЬНО

- **Монстры/лунные рыбы**: формула `Цена = round(p × Вес(кг) × 0.515)` — подтверждена на 26/26 видах, коэффициент 0.515 ± 0.009. Надёжно, можно использовать.
- **Обычная рыба**: формула **не подтверждена**. Временно используется немасштабированная `192 + вес(г)×0.022` (вес ≤2000г) / `236 + (вес(г)-2000)×0.013158` (вес >2000г) — помечена как «предварительная» с пометкой в данных. Противоречивые калибровочные данные (Щука Травянка на 1кг и 3кг дают разные коэффициенты при попытке масштабировать по `p`). Если появятся новые точные скриншоты продажи обычной рыбы — стоит пересмотреть.
